## Alternative concept - pandas instead of csv + loops
`pandas_vs_loops.py` runs the same rules with `read_csv`, `to_numeric(errors="coerce")`, `drop_duplicates`, `groupby().ffill()`. Both give the same number of rows and the same pm25 total.

| rows | loops time | loops memory | pandas time | pandas memory | speed-up |
|---|---|---|---|---|---|
| 1,000 | 0.014 s | 2.4 MB | 0.008 s | 2.6 MB | 1.8x |
| 100,000 | 1.401 s | 61.5 MB | 0.112 s | 37.3 MB | 12.5x |
| 1,000,000 | 15.387 s | 610.7 MB | 1.315 s | 305.4 MB | 11.7x |

Both are O(n) in time and O(n) in memory because both keep the cleaned rows. pandas is faster by a constant factor (the work runs in compiled code); for 1,000 rows pandas startup cost cancels the advantage. The loop version uses more memory because every row becomes a Python dictionary. (Each method ran in its own process; I did not use tracemalloc for timing because it slows Python loops a lot.)
