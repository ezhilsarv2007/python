# Task 10 - Compare Expectations with Execution (K4)

**Run:** `python task10_compare.py` (uses `milk_calculator.py` copied from Task 9)

## Findings (seeded random data, so results repeat)
* **Dataset A (litres to 0.1 L):** float and Decimal differ only by ~1e-10 (300 payments) to ~1e-6 (150,000 payments). Every amount has at most 2 decimals, so rounding each payment or only the total gives the *same* bank amount.
* **Dataset B (litres to 0.01 L):** rounding only the total is wrong by Rs 0.16 / 2.56 / 64.58 (300 / 6,000 / 150,000 payments); float with Python `round()` per payment is wrong by up to Rs 67.40 because Python rounds ties to even while the bank rounds halves up.
* Decimal takes about 4-8x longer than float, but 150,000 payments still need only ~0.25-0.4 s.
* **Reason:** binary float error + wrong rounding rule. Correct method: Decimal, round *each* payment half-up, then add.

## Alternative concept - rate table (dictionary)
Lookup is O(1) per entry and so is recalculation, but lookup is ~15x faster in practice (150,000 entries: ~25 ms vs ~400 ms). Extra space O(k) for k distinct (fat, snf) pairs (918 pairs = ~37 KB); build cost ~100 ms; the table must be rebuilt after a rate revision.
