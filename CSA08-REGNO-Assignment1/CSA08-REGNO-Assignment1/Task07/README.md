## Import styles
* `import milkrate` -> call `milkrate.payout(...)`.
* `from milkrate import payout` -> call `payout(...)`; only that name is imported.
* `import milkrate as mr` -> short alias for the same module object.

## Why the table is not printed on import
When a file is run directly its `__name__` is `"__main__"`, so the block under `if __name__ == "__main__":` runs. When another script imports it, `__name__` is `"milkrate"`, so the block is skipped. Without the guard (`milkrate_noguard.py`) the table prints at import time - an unwanted side effect.

## Where Python looks
The folder of the running script (`sys.path[0]`), then the standard library and installed packages (rest of `sys.path`). A loaded module is cached in `sys.modules`.

## Alternative concept - copying functions into every script
A rate change must then be edited in k files instead of 1. Import cost is paid once (~100 microseconds) and each later import is a dictionary lookup in `sys.modules` (~0.5 microsecond).
