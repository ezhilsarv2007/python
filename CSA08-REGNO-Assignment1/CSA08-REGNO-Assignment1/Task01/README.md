# Task 1 - Understand the Problem and Identify the Data (K4)

**Run:** `python task01_analysis.py`

## What the program shows
* **Inputs / outputs** with Python type and a justification: `farmer_id`, `shift` = `str` (labels, never calculated); `litres`, `fat`, `snf`, `rate`, `amount`, totals = `Decimal` (fractional money values must be exact); counts = `int`.
* **Named constants:** base rate, standard fat/SNF, step size, step values, valid ranges, payment cycle.
* **Rules R1-R7:** litres > 0, fat 2.0-7.0, SNF 7.0-10.0 (assumed), shift M/E, non-empty ID, round every payment to the paisa, ten-day total = sum of rounded payments.
* **Assumptions A1-A5** (including the SNF range, which the question does not give).

## Alternative concept - three variables per farmer
Design A (`litres1, fat1, snf1 ...`) needs 900 names and 601 source lines for 300 farmers, 18,000 names and 12,001 lines for 6,000 farmers, and the *program must be edited* whenever a farmer is added. Design B (one tuple per entry in a list) is 3 lines for any `n`.
* Time: **O(n)** for both. Space: both hold O(n) data, but design A's *code and symbol table* also grow with n; design B's code is O(1).
* Only design B scales to 150,000 farmers.
