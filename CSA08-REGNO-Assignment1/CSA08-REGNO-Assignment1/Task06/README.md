# Task 6 - Organise the Logic into Functions (K3)

**Run:** `python task06_functions.py`

| function | parameters | returns |
|---|---|---|
| `rate_per_litre(fat, snf)` | two floats | rate (float, 2 decimals) |
| `payout(litres, fat, snf)` | three floats | amount (float, 2 decimals) |
| `ten_day_total(entries)` | list of tuples | total (float, 2 decimals) |

* **Return vs print:** `show_payout()` prints and returns `None` - nothing can be calculated with it; `payout()` returns a value that can be reused.
* **Scope:** a function may *read* global constants. Assigning to `BASE_RATE` inside a function creates a local name (`UnboundLocalError` if it reads first). Never rebind rate constants in functions.
* Every function has a docstring (`help(payout)` shows it).

## Alternative concept - one long script / lambda
Same totals, all O(n) time and O(1) extra space. Measured difference between functions, inline code and lambda is within timing noise (150,000 entries: ~140-160 ms each), so call overhead is not a reason to avoid functions. Functions remove repeated code, give one place to fix bugs and allow testing.
