## Key results
* Types: `10` int, `10.0` float, `"10"` str, `True` bool (a subclass of int, so `True + True == 2`), `[10, 8.5]` list.
* `7 / 2 = 3.5`, `7 // 2 = 3`, `7 % 2 = 1`, `-7 // 2 = -4` (floor goes toward minus infinity).
* `0.1 + 0.2 == 0.3` is **False** (0.30000000000000004): 0.1 and 0.2 have no exact binary form.
* **TODO 1:** `float: 33400.30000000061`, `Decimal: 33400.30` - matches the expected output.
* `Decimal(float("33.40"))` copies the binary error (`33.3999999999999985789...`) so the total becomes `33400.29999999999857893118278`. Always create a Decimal from a **string**.
* `int(33.40 * 100) = 3339` loses a paisa because `33.40 * 100 = 3339.9999999999995`.

## Alternative concept (measured in `task02_alternatives.py`)
| method | exact? | memory per value |
|---|---|---|
| plain float | no (error grows with n) | 24 bytes |
| float + `round()` each step | exact in these tests, but not guaranteed | 24 bytes |
| integer paise | yes | 28 bytes |
| Decimal | yes | 104 bytes |

All are O(1) per addition and O(n) for n payments. Decimal is recommended: exact, readable and has rounding modes.
